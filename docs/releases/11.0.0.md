# Findomain 11.0.0

Findomain 11 is a rewrite around an immutable configuration and a per-target
session. The passive source set grew from 14 to 55, and the scanning stages
that used to be built in are now delegated to the tools that specialise in
them.

If you are upgrading from 10.0.1, read the breaking changes first. If you ran
one of the betas, the last section lists what changed since 11.0.0-beta.2.

Grab the binary for your platform from the assets below, pull
`edu4rdshl/findomain:11.0.0` from Docker Hub, or build from the tag:

```
git clone --branch 11.0.0 https://github.com/Findomain/Findomain
cd Findomain && cargo build --release
```

## Breaking changes

- **`--external-subdomains` was removed.** Findomain no longer runs amass or
  subfinder for you. Run them yourself and import the result, which also lets
  you keep their own flags:

  ```
  subfinder -d example.com -silent > subfinder.txt
  amass enum -d example.com && amass subs -d example.com -names -show > amass.txt
  findomain -t example.com --import-subdomains subfinder.txt amass.txt -r
  ```

- **SQLite is now the default database.** A monitoring run with no database
  flags used to reach for PostgreSQL on localhost with the default credentials;
  it now writes to `./findomain.db`. To keep using PostgreSQL, pass at least one
  of `--postgres-user`, `--postgres-password`, `--postgres-host`,
  `--postgres-port` or `--postgres-database`, or set `postgres_connection` in
  the configuration file or `FINDOMAIN_POSTGRES_CONNECTION` in the environment.
  Naming any of those switches the backend back to PostgreSQL.

- **The built-in port scanner was replaced by nmap.** `--pscan`, `--iport` and
  `--lport` now drive nmap, so nmap has to be installed for them to work.
  `--parallel-ip-ports-scan`, `--tcp-connect-threads` and `--tcp-connect-timeout`
  are gone; `--nmap-full`, `--nmap-syn`, `--min-rate`, `--nmap-host-timeout` and
  `--nmap-arg` replace them.

- **The Windows assets were renamed** to `findomain-windows.zip` and
  `findomain-windows-i686.zip`. A script downloading
  `releases/latest/download/findomain-windows.exe.zip` gets a 404 from this
  release on.

- **hjson configuration files are no longer read.** The supported extensions are
  `toml`, `json`, `ini` and `yml`.

- **`crtsh` is a single source identifier now.** It covers both the database
  mirror and the JSON API, so `--exclude-sources crtsh` excludes both.

- **`threatcrowd` was dropped**, the service no longer answers.

- **The library API changed completely.** Every module was renamed or replaced.
  Findomain is used almost exclusively as a binary, so this is a deliberate
  break rather than a deprecation cycle.

- **The minimum supported Rust version is 1.89.**

- `--threads` still works but is deprecated. Use `--lightweight-threads`.

## Passive sources: 14 to 55

42 new sources: ahrefs, alienvault, arquivo, bevigil, binaryedge, builtwith,
censys, certcentral, chaos, circl, commoncrawl, crtname, deepinfo, detectify,
dnsdb, dnslytics, dnsrepo, fofa, hackertarget, hunter, intelx, leakix,
maltiverse, mnemonic, netlas, onyphe, passivedns360, passivetotal,
pentesttools, publicwww, pulsedive, quake, shodan, socradar, spamhaus,
subdomaincenter, threatbook, ukwebarchive, wayback, whoisxmlapi, zetalytics,
zoomeye.

Each one takes its credential from the configuration file or a `FINDOMAIN_*`
environment variable; the ones that work unauthenticated run with no setup.
`--exclude-sources` accepts every identifier and `--help` lists them.

`--list-keys` prints every source that takes an API key, the configuration key
and the environment variable that set it, and whether one is configured: how
many, never the value. It also says what the absence means for that source,
skipped entirely or run on the free quota.

Paginated sources walk their cursor to the end instead of reading the first
page, and crt.sh is queried through its public PostgreSQL mirror with the JSON
API as a fallback, which returns considerably more than the API alone.

## Time budgets

A dead API used to be able to hold a run open indefinitely. Three controls now
bound it:

- `--source-timeout`, seconds for a single request to a source. Default 30.
- `--source-budget`, seconds the whole source stage may take, 0 for no limit.
  Default 300.
- `--archive-budget`, seconds the web archive indexes may spend inside that
  budget. Default 20, because those four are the slowest by a wide margin.

The budget is enforced at the single point every source request passes through,
so it applies to paginated sources as a whole rather than per page.

## External scanners

Three optional stages, each running only against hosts the HTTP check confirmed
as live, and each skipped with a message rather than an error when its binary is
missing:

- **nmap** for port scanning: `--pscan`, `--nmap-full`, `--nmap-syn`,
  `--min-rate`, `--nmap-host-timeout`.
- **nuclei** for vulnerability templates: `--nuclei`, `--nuclei-templates`,
  `--nuclei-severity`, `--nuclei-tags`, `--nuclei-exclude-templates`,
  `--nuclei-rate-limit`, `--nuclei-timeout`.
- **ffuf** for content discovery: `--ffuf`, `--ffuf-wordlist`, `--ffuf-threads`,
  `--ffuf-recursion`, `--ffuf-recursion-depth`.

All three take repeatable passthrough arguments so anything Findomain does not
expose is still reachable:

```
findomain -t example.com --nuclei --nuclei-arg -H --nuclei-arg "X-Api-Key: secret"
findomain -t example.com --pscan --nmap-arg --reason --nmap-arg --max-rtt-timeout --nmap-arg 300ms
```

The same lists are settable from the configuration file as `nmap_args`,
`nuclei_args` and `ffuf_args`. Findomain appends its own output flags after
yours, so the format it parses cannot be redirected away by accident.

nuclei findings are printed the moment nuclei reports them. In monitoring mode
every actionable finding (low and above) is also posted to the webhooks as it
arrives; informational ones go to stdout and the email report only.
`smart_alerts_webhook` (configuration file or
`FINDOMAIN_SMART_ALERTS_WEBHOOK`) routes them to a dedicated Discord or Slack
channel, the same key findomain-plus used. `--nuclei-timeout` defaults to 0,
no limit; when set, nuclei is stopped at the deadline and whatever it reported
until then is kept.

## Other new features

- **SQLite backend**: `--sqlite <file>` or `FINDOMAIN_SQLITE_PATH`. Both
  backends share the same schema, the same upsert behaviour and the same
  queries.
- **Email reports over SMTP**: `--smtp-server`, `--smtp-port`, `--smtp-user`,
  `--smtp-password` and `--email-to`, repeatable for several recipients. The
  report carries the new subdomains plus whatever nuclei and ffuf found.
- **Permutations**: `--permutations` derives extra candidates from what was
  discovered and resolves them, with `--permutations-wordlist` for your own
  list.
- **CNAME tracking**: `--cname` adds the alias each resolved subdomain points
  at as a trailing column.
- **Configuration file lists**: TOML, JSON and YAML arrays keep their entries
  verbatim, so a passthrough argument may itself contain a comma.

## Docker image and release assets

The image is now built for `linux/amd64` and `linux/arm64` (it was amd64 only)
from the same static binaries this release ships, and tagged both `latest`
and `11.0.0`. Nothing is downloaded while it builds, so it always matches its
release. The working directory and entrypoint are unchanged, so existing
`docker run` commands keep working.

`findomain-aarch64-musl.zip` is new: a static aarch64 build, the one the arm64
image is made from, which also runs on Alpine and other musl systems where the
glibc build in `findomain-aarch64.zip` does not.

## Fixed

- Webhook alerts were lost when Discord or Slack rate limited them (#327). A
  first run with a thousand new subdomains is fourteen Discord messages sent
  back to back, and Discord allows five per two seconds; the rest were
  dropped, and since the results were already stored they were never alerted
  again. A 429 is now waited out for the `Retry-After` the service sends.
  `--webhook-max-wait` and `webhook_max_wait` cap the total wait per message;
  0, the default, means no cap.
- `--ipv6-only` returned IPv4 addresses. It now resolves, reports, stores and
  port scans over IPv6 end to end.
- The monitoring summary filtered hosts by IPv4 address, so `--ipv6-only`
  combined with monitoring reported nothing on every run.
- Re-running a target failed on the unique name constraint instead of
  refreshing the stored row. Both backends now upsert.
- A broken pipe, for example `findomain -t example.com | head`, dumped core.
  It now exits the way every other command line tool does.
- Non-UTF-8 input on stdin panicked. Invalid bytes are now replaced and the
  line is discarded by validation.
- Screenshots and external tools panicked when their output directory was not
  writable.
- Targets given with a scheme, a port, a path, surrounding whitespace or a
  trailing dot are now normalised instead of being rejected. Hosts fed to
  `--as-resolver` are still taken verbatim, because `--no-resolve` needs the
  URL intact.
- `--query-database` and `--query-jobname` no longer need a reachable
  PostgreSQL server to answer from a local file.

## Security

Dependencies are updated across the tree and `cargo audit` reports nothing.
The advisories that reached the binary were a vulnerable bundled SQLite
(RUSTSEC-2026-0459), certificate validation trusting distrusted emSign
intermediates (RUSTSEC-2026-0382, RUSTSEC-2026-0383), and three in the
PostgreSQL client (GHSA-5x78-73v4-xg6w, GHSA-rgqc-3x5p-6gwg,
GHSA-3gjw-f78c-vvpw).

## Requirements

Findomain itself has no runtime dependencies. The optional stages need their
binary on `PATH`: nmap for `--pscan`, nuclei for `--nuclei`, ffuf for `--ffuf`,
and Chromium or Chrome for `--screenshots`.

## Changes since 11.0.0-beta.2

- New source: crt.name (`crtname`), free without a key at 100 requests per IP
  a day (#437). It only answers for a registrable domain.
- The minimum supported Rust version moved from 1.88 to 1.89, required by the
  updated SQLite bindings.
- The dependency updates and advisories listed under Security.
- The installation docs had broken links to the Linux, Aarch64, NixOS and
  Docker sections, and claimed every binary was 64-bit.
